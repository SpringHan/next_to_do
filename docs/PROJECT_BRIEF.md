# 项目背景

**以下内容为最初目标。**

### 程序内部逻辑

程序主界面展示今天的代办事项，按时间和顺序进行排列。  
代办事项可以分为两类：由时间框定的(`time-bounded`)和由顺序框定的(`order-bounded`)。

- `time-bounded`
  由时间框定的事项可以按时间和日期设置其 deadline 。

- `order-bounded`
  由顺序框定的事项与具体时间和日期无关，它可以显示在任何一天的代办列表中。但它有单独的属性(`prev_item`)，用来确定它的前一项（可以是 time-bounded 事项）是什么，当然，也可以没有前一项。
  `Order-bounded` 事项的展示优先级高于 `time-bounded` 事项。如果某个事项没有前一项，它就会显示在列表最上面。

### 程序界面与操作细节

1. 程序中所有能用鼠标操作的功能都需要增加对应的按键实现，按键为 TUI 的那种实现，而不是全部都需要用前缀键修饰的快捷键，且按键需要能够配置。
2. 程序的代办事项的数据和配置文件都存放在 `~/.config/next_to_do/` 目录下。
3. 该项目运行在 Linux 的 Niri wm 下，配合 `waybar` 进行使用，因此我需要它的 GUI 界面能够显示在显示在所有窗口之上且居中。同时，需要给 waybar 提供接口，让其显示今天未完成的代办事项，格式示例（真实情况未必如此，只是这样写方便理解）： format!("{}:{}", order-bounded, time-bounded)。
4. 程序的 GUI 样式[如图所示](./sample.png)，该图是一个日历程序的展示，只其学习界面样式。采用四周圆角，黑绿白灰色搭配的风格。
